# CouponPush SEO audit — 9 September 2026

## Verified findings

The supplied Semrush screenshot is dated 10 May 2026 and covers only 100 crawled pages. Its counts should not be treated as a current full-site audit.

The live check fetched the 40 URLs advertised by both public sitemaps. All returned HTTP 200, had one matching canonical and no detected noindex directive or X-Robots-Tag. Titles and descriptions were unique within that set. This does not establish Googlebot access or rule out duplicate content elsewhere.

Of 36 distinct image URLs on those pages, 23 returned 404. Seventeen store logos were incorrectly sent to api.couponpush.com; all seventeen were verified to return image responses on media.couponpush.com. Five coupon/deal images were absent on all three first-party hosts. One external Amazon campaign image was also missing.

HTTP currently returns 200 instead of redirecting to HTTPS. The www hostname failed DNS resolution from the audit environment. The legacy /store/cetaphil/ URL returns 404 instead of redirecting to /store/cetaphil-coupon-code/. An invented store URL correctly returns 404. The public export contains Apache redirect rules, but these are not taking effect on the live service.

Evidence: live-indexing-audit.json, image-origin-check.json, live-http-check.json in this directory. These requests used an ordinary audit user agent, not verified Googlebot.

## Implemented locally

- Corrected the default store media origin and normalization of old API-hosted upload URLs in the saved snapshot and API service.
- Added explicit fallbacks for the six confirmed missing images using existing site assets. These are valid in the initial HTML, without relying on JavaScript error handlers. Original source data remains available for later image restoration.
- Fixed homepage and trending-card handling of local asset paths so they are not prefixed with the API host.
- Fixed the export SEO checker to traverse all robots-declared sitemaps, including the blog sitemap and sitemap indexes. Added duplicate title/description detection.
- Added reproducible live and export image checks.

The production export is rebuilt in frontend-next/out. In the follow-up, the catalog was refreshed to 27 store profiles and 157 offers. The prior snapshot is backed up at tmp/catalog-before-indexing-refresh-2026-09-09.json. Existing banner content was explicitly retained because the banner API returns HTTP 500. Existing unrelated source edits were preserved. Production hosting changes have not been confirmed; publishing the Git changes is separate from verification of a live deployment.

The follow-up also adds 66 permanent Cloudflare-compatible legacy redirects, corrects the Apache HTTPS rule for reverse proxies, and sanitizes imported store HTML. Kapiva's imported description contained an entire HTML document with a second canonical pointing at the merchant; this is now removed before rendering. Nine new logos were verified on the API host and receive explicit origin overrides.

## Indexing and remaining actions

The local release intentionally marks individual coupon pages and search results noindex. After the refresh, Blinkit, Snitch, Kapiva, additional merchants and populated categories qualify for indexing. Seven store URLs remain excluded: Domino's, the empty legacy Dot & Key profile, Lenovo, Myntra, Swiggy and Zomato have empty inventory; Decathlon lacks useful merchant-specific copy and its API profile incorrectly points to Amazon. The newer /store/dot-key/ page has inventory and is indexable. See indexability.csv for exact URLs. These are local-release findings, not a claim about Search Console's reported exclusions. The remaining empty or incomplete profiles need supported offers or useful reviewed content.

1. Deploy the rebuilt frontend through its existing hosting workflow. If NEXT_PUBLIC_STORE_MEDIA_URL is configured in the hosting build, remove the obsolete API-host override or set it to https://media.couponpush.com.
2. Apply permanent HTTP-to-HTTPS and legacy URL redirects at the actual hosting layer. The release includes public/_redirects for Cloudflare static hosting and public/.htaccess for Apache. On Cloudflare, enable Always Use HTTPS for couponpush.com; the static redirect file cannot replace that zone setting. Check www DNS/custom-domain configuration before adding its redirect. The connected Cloudflare account was inspected: it has no Pages projects, CouponPush zone or CouponPush Worker custom domain. Its Worker named frontend serves a different site. GitHub also has no deployment or Actions history identifying a deployment target. No browser session is connected. Access to the actual hosting account/project is required to publish and verify the live redirects.
3. Rerun the live audit after deployment, then resubmit https://couponpush.com/sitemap.xml and https://couponpush.com/blog/sitemap.xml in Search Console.
4. Inspect one affected canonical URL in Search Console, including the exact exclusion reason, live URL test, Google-selected canonical and last crawl date. Request indexing for useful updated pages after those checks pass.

Google explains that [sitemaps and recrawl requests do not guarantee indexing](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl). [Consistent redirects, canonicals and sitemap URLs](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls) help consolidate duplicate URLs. The screenshot alone is not evidence of a Google penalty or a specific rejection reason.
